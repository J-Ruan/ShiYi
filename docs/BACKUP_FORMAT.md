# 加密备份格式

文件扩展名 `.shiyi`，不是可直接解压的 ZIP。内部 ZIP 含 UTF-8 `manifest.json` 和 `media/<UUID>.img` 原始图片。JSON 存储格式版本、所有实体、关联、设置、每张图片的 SHA-256；图片不会遗漏或再次压缩重编码。

加密封装版本 2：

- 固定头 `SHIYI002`（8 字节）、16 字节随机盐、12 字节随机基础 nonce。
- PBKDF2-HMAC-SHA256，310,000 迭代，256 位密钥；密码不写入文件或设置。
- 按最多 1 MiB 明文块进行 AES-256-GCM 加密，单块完整认证后才写入临时文件，避免处理大型图片集时将整个备份加载进内存。
- 每帧：4 字节大端明文长度 + 密文 + 16 字节认证 tag。
- nonce 为基础 nonce 后 8 字节与 64 位帧序号 XOR；同一文件的 nonce 不重复。
- AAD 为完整固定头、8 字节帧序号和 4 字节长度。篡改、重排、移除帧均导致验证失败。
- 末尾必须有长度 0 的认证终止帧，且后面不得再有数据，拒绝截断和追加数据。

恢复只接受清单及图片路径，无任意文件提取。JSON 上限 32 MiB，图片 / 总解密数据有容量上限（总计 8 GiB，单图最高 4 GiB 且受设备可用空间限制）。低空间、错误密码、坏 tag、无效外键等错误均不能覆盖原记录。准备恢复的临时文件在取消、完成或 ViewModel 清除后删除。应用重启时清除历史恢复临时目录。

清单格式 version 2 只导出可迁移主题，设备 PIN / 生物识别 / 通知 / 最近备份时间 / 大小 / 位置保持当前手机配置。读取兼容 1.0.0 的清单格式 1（缺少 deletedAt 时为 null），同样只恢复主题。新清单包含回收站记录及原图；旧 1.0.0 不支持读取清单 2。更高未知清单版本明确拒绝，先升级应用。

本地数据库与原图的设备密钥不进入备份。导出时解密原图字节写入临时 ZIP，再通过原有 SHIYI002 密码封装；新手机验证备份后使用自己的 Keystore 密钥重新加密。备份密码是跨设备恢复的唯一凭据，不能复用旧设备 Keystore。
